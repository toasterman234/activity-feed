# ADR-015: Planning reviews require verified grounding and resolved decisions

## Status

Accepted

## Date

2026-07-27

## Context

An approved Activity Dashboard notification plan described a generic Prisma
social application with users, posts, reactions, comments, Firebase, and a
second service worker. The real application uses PostgreSQL through `pg`,
contains no Prisma schema, and already builds a Serwist service worker.

The failure crossed four boundaries:

1. The initiating message said "see above", but the captured thread contained
   no upstream specification.
2. Channel and review agent invocations ran without repository tools.
3. The review prompt received conversation, tasks, and artifacts, but no
   server-verified project facts.
4. The review correctly returned four unresolved architecture decisions, yet
   the approval endpoint allowed the plan to become terminal.

The final condition was the direct control failure. The other conditions made
an ungrounded result likely; approval behavior made it authoritative.

## Decision

Planning review now receives a small, deterministic project-grounding block
generated by the server. It records the inspected root, package root,
framework, database/data-layer signal, existing service worker, Prisma-schema
presence, and the evidence files used for those conclusions.

Plan-review output must separately declare:

- verified grounding evidence;
- unverified assumptions;
- decisions still needed.

Approval is rejected when grounding evidence is absent, or while either
unverified assumptions or unresolved decisions remain. The user must add
feedback, rerun the challenge, and approve the resulting grounded plan.

The review prompt also treats references such as "see above" as missing context
unless that content is actually present. It must not invent frameworks,
databases, entities, integrations, or user models.

## Alternatives considered

### Give every planning review unrestricted repository tools

Rejected as the primary safeguard. Tool access is useful, but it is slower,
less deterministic, and still allows an agent to skip inspection. Server
grounding provides a stable minimum evidence contract.

### Rely on stronger prompt wording alone

Rejected. The failed review already identified unresolved decisions. A prompt
cannot compensate for an approval endpoint that ignores its own warning state.

### Require a repository on every Planning task

Rejected. Some plans are intentionally conceptual or span multiple systems.
When no target is known, the plan must say so and remain unapprovable until the
material assumption is resolved.

### Allow approval with warnings

Rejected. Terminal approval means the plan is safe to hand into execution.
Open architecture decisions and unsupported assumptions violate that contract.

## Consequences

- A plan challenge becomes a real gate rather than advisory prose.
- Repository-specific plans carry a compact evidence trail.
- Conceptual plans can still be reviewed, but unknown material facts remain
  visible blockers.
- Existing approved reviews remain readable because the new grounding fields
  have backwards-compatible defaults.
- The initial plan editor still uses title length as its basic readiness check;
  semantic quality is enforced at review. Rich structured task editing remains
  a separate improvement.

## Regression coverage

`src/lib/plan-review-guard.test.ts` verifies that:

- this repository is identified as PostgreSQL + Serwist and not Prisma;
- unresolved decisions block approval;
- a grounded review with no open decisions remains approvable.
